# Day 90 — Graduation: The Complete DevOps Journey

## 90-Day Timeline

### Week 1–2: Linux Fundamentals

I started with the basics: `ls`, `cd`, `cat`, `grep`, file permissions, processes, users, services, and disk management.
This was the foundation. Every DevOps tool I used later depended on these Linux habits.

### Week 3: Networking

I learned DNS, IPs, ports, subnets, and how machines communicate across a network.
That made troubleshooting containers, services, and clusters much easier.

### Week 4: Shell Scripting

I wrote Bash scripts, used functions, loops, and learned how to automate repetitive work.
This was my first step from manual commands to real automation.

### Week 5: Git and GitHub

I practiced branching, merging, commits, pull requests, and GitHub workflows.
Version control became part of my daily workflow.

### Week 6–7: Docker

I learned images, containers, Dockerfiles, volumes, networking, Compose, and multi-stage builds.
I understood how to package apps so they run the same everywhere.

### Week 8–9: CI/CD with GitHub Actions

I built workflows, triggers, runners, secrets, and security-aware pipelines.
Code could now move from commit to build to deploy automatically.

### Week 10: Kubernetes

I worked with Pods, Deployments, Services, Namespaces, and RBAC.
This showed me how containers are managed at scale.

### Week 11: Terraform

I used Terraform to provision infrastructure declaratively with providers, state, modules, and workspaces.
I started thinking in infrastructure as code.

### Week 12: Ansible

I learned inventories, playbooks, roles, templates, and Vault.
This helped me manage configuration in a clean and repeatable way.

### Week 13: Observability

I used Prometheus, Grafana, Loki, Promtail, and OpenTelemetry.
I learned that knowing why something broke is just as important as making it run.

### Week 14: Helm

I created charts, templates, and values files for different environments.
Helm made Kubernetes deployments reusable and organized.

### Week 15: Amazon EKS

I worked on EKS, storage, ingress/gateway setup, IRSA, and autoscaling.
This made Kubernetes feel production-ready on AWS.

### Week 16: ArgoCD and GitOps

I practiced GitOps workflows, sync strategies, App of Apps, and deployment automation.
Git became the single source of truth.

### Week 17: Agentic AI for DevOps

I explored LLM agents, ReAct, MCP, and self-healing ideas like KubeHealer.
This was the most future-facing part of the journey.

### Week 18–19: Final Integration

I connected everything into one flow: code, build, image, deploy, observe, and recover.
That is when the full DevOps picture finally made sense.

---

## Top 5 Aha Moments

1. DevOps is not a list of tools. It is a connected system.
2. Git is not just for code storage. It is the control plane for delivery.
3. Kubernetes becomes easier once Docker, networking, and YAML make sense.
4. Observability is not optional. It is how you survive production.
5. AI can help in operations, but only when the foundation is already solid.

---

## Hardest Day

The hardest part was not one tool. It was connecting all the tools together without losing the bigger picture.

There were moments where a Kubernetes issue, a Terraform config, or a CI/CD failure felt isolated. The breakthrough came when I stopped treating each day as a separate lesson and started seeing the full pipeline. That changed how I learned, debugged, and documented my work.

## Advice for Day 1

Start small. Stay consistent. Do the hands-on work yourself.
Do not rush to memorize tools before understanding the problem they solve.

The real progress comes from:

- breaking things,
- fixing them,
- documenting them,
- and repeating the process every day.

That is how DevOps becomes real.
